# 多路视频流与异步帧获取

> 日期：2026-11-03。对应计划：`docs/多路视频流落地计划.md` V1–V7。
> 状态：V1–V7 自动 smoke 通过（V6 用 test-only client.command 验收）；未做用户长跑/多客户端实测。

## 1. 统一帧出口

```text
active 连续流 OffscreenRenderPipeline ─┐
时间片非 active MultiCameraRenderer ───┼─> CameraFrameStore.put(cameraId, frame)
                                      │       │
                                      │       └─> HTTP /camera/{id}/frame|stream
                                      │       └─> WS video.subscribe + 0x04
                                      │       └─> CaptureApi.grabFrame(cameraId)
                                      │       └─> recording camera
                                      └─> VideoFrameBus.publish（仅 active，兼容旧 0x01）
```

`CameraFrameStore` 是唯一按相机 id 的帧存储；active 帧由 `OffscreenRenderPipeline`
编码完成回调双写，非 active 由 `MultiCameraRenderer` 写入。

## 2. FrameRequest.cameraId（V1）

Java：

```java
FrameRequest req = FrameRequest.builder()
        .cameraId(2)
        .quality(90)
        .build();
FrameResult result = CaptureApi.captureFrame(req);
```

- `cameraId != null`：读取/等待该已存在相机的下一次渲染帧，不新建临时相机；
- 仍受 `timeoutMillis` 限制；
- 统一 HTTP 输出 URL 为 `/camera/{cameraId}/frame`。

WS：

```json
{"id":"c1","action":"capture","params":{"camera":2,"quality":90,"method":"file","timeout":8000}}
```

## 3. WS 多路订阅 + 0x04（V2）

控制：

```json
{"id":"v1","action":"video.subscribe","params":{"cameras":[1,2]}}
{"id":"v2","action":"video.unsubscribe","params":{}}
```

- `video.subscribe` 按连接维护相机集合；
- 有订阅的连接：只收对应相机的 0x04；
- 无订阅的连接：继续收旧 0x01（向后兼容）；
- 订阅即标记消费者，触发懒渲染。

0x04 线格式：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | magic `0x04 'C' 'A' 'P'` |
| 4 | 4 | cameraId，LE |
| 8 | 8 | timestampNanos，LE |
| 16 | 2 | width，LE |
| 18 | 2 | height，LE |
| 20 | 2 | 保留/对齐（当前头 22B，JPEG 从 22 开始） |
| 22 | N | JPEG |

> 实现常量：`CaptureConstants.MULTI_VIDEO_CHANNEL_HEADER_BYTES = 22`；
> `MultiChannelVideoCodec.encode/decode/hasMagic`。

## 4. 异步 grabFrame（V3）

```java
CompletableFuture<JpegFrame> future = CaptureApi.grabFrame(2, 5000);
```

- 指定 cameraId：等待该相机下一次渲染帧，不新建/销毁临时相机；
- 指定参数版本 `grabFrame(CameraCreateParams, timeout)` 语义不变；
- 等待者通过 `CameraFrameStore.awaitNextFrame` 登记，`put` 时唤醒；
- 消费者标记会触发 V4 懒渲染。

## 5. 帧预算/懒渲染（V4）

配置：

| key | 默认 | 说明 |
|---|---|---|
| `multi_camera_fps` | 4 | 非 active 相机目标帧率；0=关闭时间片 |
| `multi_camera_budget_ms` | 4 | 每次 AFTER_LEVEL 多路渲染预算（ms） |

行为：

- 无消费者的非 active 相机不渲染（`CameraFrameStore.hasConsumer`）；
- 消费者：HTTP 读取、WS 订阅、grabFrame 等待、录像；
- 消费者 TTL：`MULTI_CAMERA_CONSUMER_TTL_MS = 2000`；
- 有消费者时按 round-robin，在预算内渲染；
- 无多路消费者时 `multi_rendered` 不增长。

## 6. 录像按相机（V5）

- `RecordingParams.cameraId`：0=active，>0=指定相机；
- WS `recording.start` 支持 `camera`（别名 `cameraId`）；
- 视频循环从 `CameraFrameStore.get(cameraId)` 取帧，active 无 store 帧时回退旧 bus；
- 音频仍由 `audioChannel` 独立选择。

## 7. 游戏指令（V6）

```text
/captureapi capture camera:2 filter:grayscale quality:90
/captureapi record start camera:2 audio:true
/captureapi camera status      # 每路 lastFrameAgo
```

`ParamParser` 仍为通用 key:value；`camera:<id>` 映射到 `FrameRequest.cameraId`。

## 8. 性能护栏（V7）

`/health` 新增：

- `multi_camera_fps` / `multi_camera_budget_ms`；
- `multi_rendered` / `multi_consumers` / `multi_last_frame_ms`；
- `multicam_cached_cameras` / `multicam_interval_ms`。

超预算仅告警，不硬拒；默认值可配置。

## 10. 限制

- 多路渲染仍是同一渲染线程顺序时间片，不是并行 FBO 帧；
- `multi_camera_fps` 是目标值，受主渲染/预算限制；
- 0x04 与旧 0x01 并存，客户端必须按 magic 分流；
- 每路仅保留最新帧；
- V6 游戏内指令已用 test-only `client.command` 自动验收；
- 未做多客户端/长时录像/内存压力实测；test-only `client.command` 仅 dev 门控下可用。
