## 一、目录与发现（I8.1.1）

- 目录：`config/captureapi/filters`（`filter_directory` 可配）；
- 首次启动自动创建目录 + `README.txt`（含格式示例与 op 表）；
- 一文件一滤镜（`.json`）；非法文件跳过并 WARN，不阻塞其余；清单原子替换；
- 热重载：WS `filter.reload`（也可重启客户端）。

## 二、JSON 参数式格式（I8.1.2）

```json
{"name":"my_filter","version":1,"ops":[
  {"type":"brightness","params":{"value":0.1}},
  {"type":"grayscale"}
]}
```

| op | 参数 | 范围 |
|---|---|---|
| `brightness` | value | [-1,1]（加性） |
| `contrast` | value | [-1,1] |
| `saturation` | value | [0,2] |
| `hue` | degrees | [-180,180] |
| `grayscale` | — | Rec.709 加权 |
| `invert` | — | 反色 |

- 按数组顺序执行；未知 type/越界/缺参 → 该滤镜加载失败（四要素：文件+op 序号+原因+修正建议）；
- 内置 `grayscale` 随 jar，无需用户文件（I8.1.3）。

## 三、应用链路（I8.1.5）与故障隔离

- 编码前（`EncodingPipeline`）与实时调取编码前应用选中滤镜；无滤镜默认原帧；
- 单滤镜运行异常 → 禁用该滤镜、WARN、捕获流继续；
- 仅作用于离屏捕获流，主画面零影响；
- WS 控制：`filter.list` / `filter.set`（`name`，空=关闭）/ `filter.reload`。

## 四、GLSL-as-JSON（I8.1.4，未启用）

## 五、dev 运行时证据（2026-11-01）

```
filter.list -> filters=["grayscale"]
filter.set grayscale -> selected=grayscale
filter.set nope -> E_NOT_FOUND
filter.reload（放入 test_bright.json 与越界 bad.json）-> filters=["grayscale","test_bright"]（bad 被跳过）
filter.set test_bright -> selected=test_bright
```
