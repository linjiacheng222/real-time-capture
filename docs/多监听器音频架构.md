# 同客户端多 Listener 音频架构

> 日期：2026-11-03。状态：Phase 0–4d 后端首版，自动 smoke PASS；用户听感/长跑/Oculus 未测。
> 计划来源：`docs/第二阶段深化计划.md` P1.1/P1.2 + 已批准的多 listener 落地计划。

## 1. 目标

同一个 MC 客户端内同时存在多个 OpenAL listener：

- Player listener：玩家实际听到的音频，始终固定在玩家；
- Camera listener：每台相机一套，供相机视角音频采集；
- Virtual listener：音频截面临时虚拟位置。

每个 listener 有独立 context、独立声源镜像、独立混音、独立 PCM ring。

## 2. 为什么需要多 context

OpenAL 一个 context 只有一个 Listener；单 context 无法同时产生两份不同 listener 的混音。
本实现采用：

```text
Player context（现有 loopback；Java Sound 播放）
Camera context 1..N（每相机独立 loopback；只采集）
Virtual context（音频截面）
```

所有 worker 使用 `ALC_EXT_thread_local_context` 的 `alcSetThreadContext`，避免抢走
Minecraft player context；所有 context/current/capabilities/source 创建都在各自 worker 线程完成。

## 3. 声源镜像

Minecraft `Channel` 是真实声源入口：

- `Channel.attachStaticBuffer` → 复制 `SoundBuffer.data/format` 到各 listener context；
- `Channel.attachBufferStream` → `TeeAudioStream` 复制流式 PCM；
- `play/pause/unpause/stop/position/pitch/volume/looping/attenuation/relative/destroy`
  通过 `AudioSourceMirror` 广播到各 listener 的独立 AL source；
- 原 player Channel/context 行为不改变；
- player context 的 listener 永远固定在玩家，feature 开启时不再跟随相机/虚拟。

关键类：

| 类 | 职责 |
|---|---|
| `AudioChannelRegistry` | 通道生命周期、primary、virtual section、snapshot |
| `AudioChannelCoordinator` | 从 CameraManager 同步 camera channel |
| `AudioContextWorker` | 每通道独立线程/context/渲染/命令队列 |
| `AudioPcmRing` | 每通道 PCM ring |
| `AudioSourceMirror` | static/stream 声源镜像 |
| `TeeAudioStream` | 流式 PCM tee |
| `MultiChannelAudioCodec` | WS 0x03 多通道音频帧 |

## 4. 通道与主出口

- 通道 id：`0=PLAYER`、`1..N=CAMERA(cameraId)`、`-1=VIRTUAL`；
- `audio_primary_channel`：
  - `camera`（默认）：primary = active 相机通道；无相机回退 player；
  - `player`：primary = player；
- legacy WS 0x02、`latestAudioChunk()`、录像默认都读 primary；
- 0x03 只推**额外订阅**通道，primary 不重复推。

## 5. 配置

| key | 默认 | 说明 |
|---|---|---|
| `audio_multi_listener_enabled` | false | 总开关；重启生效 |
| `audio_max_listener_channels` | 2 (1..4) | 相机 listener 上限（不含 player/virtual） |
| `audio_primary_channel` | camera | camera/player |

dev 属性（不写 TOML）：

- `captureapi.debug.multilistener_feature=true`：强制开启 feature；
- `captureapi.debug.multilistener_mirror=true`：Phase2 自测；**不要与普通相机 smoke 混用**（会创建/删除 camera 1 冲突）；
- `captureapi.debug.multilistener_stream=true`：Phase3 流式自测；
- `captureapi.debug.multilistener_channels=true`：Phase1 合成通道自测。

## 6. Java API

```java
CaptureApi.audioChannels()          // List<AudioChannelInfo>，含 PLAYER/VIRTUAL/CAMERA
CaptureApi.latestAudioChunk()       // primary 最近 PCM（非消费）
CaptureApi.latestAudioChunk(id)     // 0=player；相机=cameraId；-1=virtual
CaptureApi.primaryAudioChannelId()
CaptureApi.multiListenerEnabled()
CaptureApi.grabAudioSection(x,y,z,chunks) // feature 开启时走 virtual channel
```

`AudioChannelInfo`：`id/kind/cameraId/active/written/dropped/errors`。

## 7. WS 接口

控制 action：

- `audio.channels.list`；
- `audio.channels.peek`：`channel`，返回 found/start/end/sampleCount/rms/peak；
- `audio.subscribe`：`channels:[...]`，per-connection；
- `audio.unsubscribe`；
- `audio.section`：虚拟 listener PCM 统计。

0x03 二进制：

```text
[4B magic = 0x03 'C' 'A' 'P'][4B channelId LE][8B start][8B end][4B sampleCount][PCM]
```

- 28B 头；
- 旧 0x02 音频/视频帧没有 type 字节，客户端必须按 magic 识别 0x03；
- primary 不重复推 0x03。

## 8. 录像

`RecordingParams` 增加 `audioChannelId`：

- `-1`：primary；
- `0`：player；
- `>0`：camera；
- WS `recording.start` 可传 `audioChannel`；
- 录像音频使用通道 snapshot，不消费 WS ring。

## 10. 已知限制

- 自动化窗口失焦会全局 pause；self-test 在 debug mirror 下跳过 pause 镜像，真实 pause/unpause 需聚焦窗口实测；
- 相机/虚拟音频的用户听感、方向性、零扰动尚未验收；
- feature 默认关闭；开启后 context 数/软件混音 CPU 开销需实测；
- 相机通道创建在 client tick 同步等待 worker 启动，可能造成启动 hitch（后续可异步化）；
- 旧 0x02 帧没有 type；0x03 使用 magic 区分；
- max listener 通道默认 2，未承诺 8 路。
