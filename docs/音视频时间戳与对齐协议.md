# 音视频时间戳与对齐协议（M5）

> 状态：**T5.1/T5.2 规则与文档完成、T5.3 监测代码完成**（2026-11-01）；10 分钟单调性/偏差/对拍/Python 实际播放测试归测试分计划。
> 协议版本：v0.5 语义；契约字段变更须先改本文档。对应 I5.1~I5.3、I4.2.1/I4.2.2。

## 一、时间戳生成规则（T5.1，冻结）

### 视频帧
- 唯一语义：**PBO 回读完成时刻**（数据就绪）；实现锚点 `PboPairResource.readback/readbackImmediate` 调 `CaptureClock.nowNanos()`，实时调取帧同语义；
- 禁止使用渲染发起/编码完成等其它时刻；打标点一处（readback）为**契约点**。

### 音频块
- **区间**：`startNanos`＝数据就绪时刻（采集线程 `CaptureClock.nowNanos()`，I3.4.1）；`endNanos = startNanos + sampleCount × 1e9 / sampleRate`（纯整数，I3.4.2）；
- 与视频对偶：两侧都是数据可用时刻，同源可直接相减。

### 单源核验（I5.1.3）
- 全源码仅 `CaptureClock` 可取时（build.ps1 红线 4 静态扫描：白名单外 0 命中）；
- 运行时互推：同步监测的交叉差与间隔统计可发现回退/跳变（见 T5.3）。

## 二、协议时间戳字段（I5.2.1，冻结候选）

WS 二进制消息都携带 **CaptureClock 纳秒原值**（int64 小端，不做毫秒换算）：

| 消息 | 偏移 | 字段 | 长度 | 语义 |
|---|---|---|---|---|
| 视频帧 | 0 | timestampNanos | 8 | 回读完成时刻 |
| 视频帧 | 8/10/12 | width/height/payloadLength | 2/2/4 | 帧元数据 |
| 音频块 | 0 | startNanos | 8 | 音频区间起点（数据就绪） |
| 音频块 | 8 | endNanos | 8 | 区间终点（整数推算） |
| 音频块 | 16 | sampleCount | 4 | 采样数 |

- 接收端统一减去会话首个时间戳即得相对时间（毫秒可读）；8B 纳秒无回绕风险；
- **不要**按到达顺序消费；到达顺序仅用于抖动缓冲。

## 三、接收端对齐约定（I5.2.2）

必须遵守：
1. 按时间戳排序/铺放，而非到达顺序；
2. 播放时钟原点 = 首个视频帧（或首个音频块）；视频按时间戳显示，音频按区间铺入播放缓冲；
3. 乱序（时间戳回退）丢弃并计数；已对账的丢拍间隙补静音。

建议（可调）：
- 抖动缓冲 50~100ms；
- 视频帧可丢旧保新，音频区间不可重叠。

## 四、四出口能力对照（I5.2.4）

| 出口 | 视频 | 音频 | 时间戳 | 对齐支持 | 说明 |
|---|---|---|---|---|---|
| WS 推流 | JPEG 二进制 | PCM 二进制 | 原生纳秒 | ✅ | 音画对齐首选 |
| MJPEG | JPEG multipart | — | 无（仅 HTTP 头可选） | ❌（豁免） | 纯视频；勿从帧间隔反推时间轴 |
| HTTP 单帧 | 裸 JPEG | — | `X-Frame-Timestamp` | 单帧轮询/原型 | 无连续音频 |
| Java API | JpegFrame/AudioChunk | AudioChunk（截面待 W-071） | 原生纳秒 | 进程内 | 二次开发 |

**MJPEG 豁免说明**：设计如此——无音频、multipart 无时间戳字段、帧间隔即生产节拍；需要对齐请用 WS 出口。

## 五、偏差监测（T5.3，代码完成）

`SyncDeviationMonitor`：
- 指标：音画交叉差 `audioMidpoint - videoTimestamp` 的滑动均值（EWMA）；时间戳回退计数；告警计数；
- 开关：`sync_monitor_enabled`（默认 false，零日志）；阈值 `warn_threshold_ms=50`（建议值）；
- 开启后秒级 `[SYNC]` 行 + 超阈值 WARN + 1 分钟趋势行；
- `/health` 暴露 `sync_delta_ms_avg/sync_delta_samples/sync_regressions/sync_warnings`；
- 判读：持续单调漂移→查 CaptureClock/节拍；无规律抖动→网络/调度噪声。
