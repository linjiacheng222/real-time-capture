# 服务端组件双端契约 v0.1（T2.9 冻结）

> 状态：**契约冻结（2026-10-31）**；实现归 M9 独立模块（需用户批准立项）与 T2.7.3 客户端侧。
> 关联：I2.9.1、T2.7.3；修改本契约需重新评审（客户端/服务端两侧唯一耦合面）。

## 一、定位

远程 MP 下客户端无法让服务端加载玩家视距外区块；方案 B 既定：**可选纯服务端 Forge 组件**（1.20.1，零客户端代码，装入服务端 mods 即生效）。本契约冻结最小四消息语义与降级路径，不预设服务端实现、限额、发布策略（全部留 M9）。

## 二、通道与版本

- Forge 1.20.1 自定义网络通道（具体 `SimpleChannel` API 待 W-050/W-060 实装确认）；
- 所有消息前置字段：`protocolVersion:int`（当前 1）；版本不匹配 → 服务端应答“不支持”，客户端进入降级模式；
- 编码细节（字节序、压缩、扩展字段）留 M9；本契约只冻结语义与字段集合。

## 三、四消息

| # | 消息 | 方向 | 载荷 | 语义 |
|---|---|---|---|---|
| 1 | HandshakeRequest | C→S | `protocolVersion` | 客户端进服/组件探测时发送，请求能力协商 |
| 2 | HandshakeResponse | S→C | `protocolVersion`, `supported:boolean`, `reason`（可选） | 支持/版本不匹配；无应答或 false → 客户端降级模式 |
| 3 | ChunkRequest | C→S | `chunks:int64[]`（ChunkPos long 增量集合，节流后） | 请求对这些区块维持“类玩家级”临时加载；可多次增量申请 |
| 4 | ChunkRelease | C→S | `all:boolean` + `chunks:int64[]` | 释放指定区块；`all=true` 表示释放该玩家全部 |
| 5 | （连接断开） | 服务端事件 | — | 服务端按连接回收该客户端全部 ticket；超时兜底回收，防包丢失滞留 |

补充语义：
- 服务端只服务**当前连接玩家**的请求，不跨玩家共享；单玩家 ticket 总量沿用 `CHUNK_TICKET_LIMIT` 护栏（运行时读原版常量，禁硬编码），超出截断并日志；
- 客户端相机关闭/暂停/退服立即发 `ChunkRelease(all=true)`；服务端组件未安装 → 客户端不发送 ChunkRequest（降级模式）并上报状态“MP 区块未同步（未安装服务端组件）”给 M4 协议层；
- 加载级别：类玩家级临时 ticket（API 形态待 W-046/W-048/W-049/W-059/W-061 实装确认），不改原版玩家视距配置。

## 四、降级路径

| 场景 | 行为 | 用户可见性 |
|---|---|---|
| 服务端无组件/握手失败 | 客户端降级：视距外区块缺失→不渲染、不报错，日志 debug 可查；M4 状态字段上报 | M4 协议显式提示（文案归 M4） |
| 版本不匹配 | 同上，附原因字符串 | 同上 |
| 申请/释放包丢失 | 服务端超时回收兜底；客户端退服再兜底 | 无感 |
| 单玩家 ticket 超限 | 服务端截断并告警；客户端保持现状 | 日志可查 |

## 五、组件形态概要

- 纯服务端 Forge jar（1.20.1），无客户端代码/资源；装入服务端 `mods/` 生效；
- 仅实现四消息受理与 ticket 生命周期；权限、对抗滥用、包压缩、多相机玩家并发、Bukkit 类服务端兼容性等 → M9 独立细化；
- 组件可选：客户端在无组件时功能降级但不崩溃（方案 B 约定）。

## 六、冻结与变更

- 本文件为 v0.1 冻结基线；T2.7.3 客户端可依据本契约开发；
- 任何字段/语义变更需主理人评审并在本文件追加变更记录；实现层扩展字段不得改变既有语义。
