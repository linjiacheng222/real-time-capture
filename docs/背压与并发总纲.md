# 跨线程并发与背压总纲（T4.6）

> 状态：**代码/健康暴露/总纲完成**（2026-11-01）；30 分钟四路并发压测、静态共享状态审计、渲染帧率对照归后续《测试分计划》。
> 关联：I4.6.1~3、M1 线程职责表、T4.2/T4.4/T4.5、M2/M3 通道。

## 一、线程与通道清单（I4.6.1）

| 通道 | 生产者（线程） | 消费者（线程） | 语义 |
|---|---|---|---|
| `VideoFrameBus`（LatestValueChannel） | 离屏渲染帧（渲染线程） | `captureapi-push`（WS 推流）、HTTP 单帧路由（HTTP 工作线程）、MJPEG（HTTP 工作线程） | 保最新丢旧；只读消费不改状态 |
| `AudioRingBuffer`（SPSC 字节环） | `captureapi-audio-capture` | `captureapi-push` | 写端永不阻塞；满丢最旧/空补静音 |
| WS 每连接发送队列（容量 32） | `captureapi-push` | 每连接 `captureapi-ws-writer` | 满即断慢连接（1013） |
| HTTP MJPEG 响应 | HTTP 工作线程（每连接） | 客户端 | 写异常/心跳失败即清理；超 5s 慢写断开 |
| 控制指令 | WS 读线程（每连接） | `CameraManager`（ConcurrentHashMap + volatile active） | 原子替换快照；不触 GL |

所有出口只从通道取数据，无绕行直连生产端；渲染线程只写视频通道、不接触网络。

## 二、降级次序（I4.6.2）

总原则：**丢旧保新、宁降级不阻塞**。过载时按低优先先降：

1. **HTTP 单帧轮询限速**（`max_qps` 默认 30，超限 429 `E_RATE_LIMIT`）——原型期最低优先；
2. **WS 慢连接断开**（发送队列满 → 1013，计数 `slow_disconnects`）；
3. **MJPEG 慢写断开**（>5s，计数 `http_slow_disconnects`；连接名额释放）；
4. **音频补静音**（环形缓冲空；计数 `audio_ring_silent`）/满丢最旧（`audio_ring_dropped`）；
5. **视频丢旧帧**（LatestValueChannel 语义，天然合并）；
6. 推流主链最后受影响（AI 视觉实时性优先）。

## 四、健康端点统一计数（I4.6.2）

`GET /health` 现含：`connections, rejected_connections, slow_disconnects, http_streams, http_slow_disconnects, video_frames_published, audio_ring_written/dropped/silent, pipeline_failed_frames, max_connections, max_qps, render_backpressure`。

M7 长跑判读：`audio_ring_dropped/silent` 与 `slow_disconnects` 的持续增长分别指向采集故障/消费慢；`pipeline_failed_frames` 指向渲染异常。

## 六、已知缺口

- 压测未执行；`max_qps` 仅简单 1 秒窗口（非精确令牌桶），高并发下的公平性待实测；
- HTTP/WS 连接上限为近似共享（`httpStreams + WS 连接数`），并发竞争下可能有少量超额；
- MJPEG 慢写超时受 OS 写缓冲影响，实际阈值需压测校准；
- 视频通道当前没有显式丢弃计数（LatestValueChannel 只保留最新，丢帧不可见），长期需要发布/消费计数器补全。
