# 统一帧获取函数（T4.9）

> 状态：**I4.9.1 参数模型、I4.9.2 文件输出、I4.9.3 HTTP 编排代码完成**（2026-11-01）；Java API 运行时调用/文件内容/HTTP TTL 过期行为待测试分计划。
> 关联：I4.9.1~3、T4.7 CaptureApi、T2.1 相机、I4.5 frame 路由、W-082/W-083/W-084。

## 一、入口

`CaptureApi.captureFrame(FrameRequest)` → `FrameResult`（同步阻塞至帧就绪；**禁止渲染线程调用**）。

- 省略相机参数：使用 active 相机当前状态；
- `temporary=true` 或显式相机参数：走 T2.2.4 临时相机调取（与流式同帧互斥）；
- position 与 boundEntity 互斥；temporary 与 continuous 互斥；
- continuous/音频截面/渲染名单等高级字段当前**明确不支持**（抛 `UnsupportedOperationException`，不假实现）。

## 二、文件输出（I4.9.2）

- 默认目录 `recording_output_dir`（`config/captureapi/recordings`）；显式 `outputPath` 会创建父目录；
- JPEG 直接写；PNG 以 JPEG 解码后 ImageIO 重编码；
- 文件名 `capture_<timestampNanos>.jpg`，存在则 `_1.._9999` 自增；**偏离说明**：计划写 `yyyyMMdd_HHmmss_SSS`，但红线 4 禁止第二时间源，故用 CaptureClock 纳秒时间戳（可排序、无墙钟依赖）；如需要人类可读文件名可后续在日志侧转换；
- 写失败抛 IOException（不崩溃）；文件内容为有效 JPEG/PNG。

## 三、HTTP 输出（I4.9.3）

- 返回 `http://{host}:{net_port}/camera/0/frame`；
- `bind_local_only=true`（默认）→ host `127.0.0.1`；LAN 开启 → 本机地址；
- 临时相机帧写入 `VideoFrameBus` 临时槽，TTL = `frame_cache_ttl_sec`（默认 30s）；TTL 内 HTTP 可读，过期后 `latest()` 返回空（HttpVideoHandler 当前为 204/404，`E_FRAME_EXPIRED` 细化待 W-084）；
- 流式相机直接返回现有帧 URL（同源）。

## 四、FrameResult

`{outputMethod, location, timestampNanos, width, height, sizeBytes}`；FILE 时 location 为实际路径，HTTP 时为完整 URL。

## 五、已知缺口

- Java API 调用无外部自动化入口，需在游戏内测试或写测试模组；
- TTL 过期 `E_FRAME_EXPIRED` 错误体未实装；
- 回调通知 URL、渲染黑白名单、PNG 元数据嵌入（W-083）未实装；
- 文件名格式按红线 4 偏离计划，需用户确认是否接受；
- 连续采集/音频截面不可用（continuous/audio 字段明确拒绝）。
