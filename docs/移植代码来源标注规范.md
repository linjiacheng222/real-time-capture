# 移植代码来源标注规范（I1.6.3）

> 状态：T1.6 实施（2026-10-31）。依据红线 5；自 M2 起每个移植 PR 强制执行。
> 原则：**宁多勿漏**——凡参考过反编译产物/源码后写出的实现，均须标注来源。

## 一、协议分类与标注义务

| 来源协议 | 允许性 | 文件级义务 |
|---|---|---|
| MIT（DebugBridge、Record-able） | 可复制/改写 | 保留原版权与许可声明；类头 `@source`/`@changes`；重大修改保留原注释 |
| MPL-2.0（Pixelshot、PuzzlesLib 代码） | 可复制/改写 | **被复用文件保持 MPL-2.0**：文件头 `// SPDX-License-Identifier: MPL-2.0` + `@source`；修改说明；NOTICES 登记 |
| GPL-3.0（Mineshot Revived） | **禁止复制任何代码** | 仅参考设计；不得出现相同/近似实现代码；设计参考在分析笔记中记录 |
| LGPL-3.0（Embeddium/ModernFix/Oculus/Rubidium） | 依赖或适配对象 | 不复制代码；依赖声明/兼容适配不产生文件义务 |

## 二、类头标注模板

```java
/**
 * <一句话职责>
 *
 * @source Record-able OpenALLoopbackCapture（V1-0.11-legacy；github.com/JoEusebe/record-able）
 * @changes 2026-XX-XX 抽取 loopback 设备初始化；去掉 Java Sound 中继，改为环形缓冲输出；
 *          适配 1.20.1 Mojmap 与 Forge 事件模型
 */
```

MPL 复用文件的文件头（Java 示例）：

```java
// SPDX-License-Identifier: MPL-2.0
// @source Pixelshot ScreenshotHandler（v20.1.0-1.20.1-Forge）
// @changes 扩展为循环离屏渲染入口；拆分 FBO 生命周期至 WorldResourceManager
```

## 三、粒度与判定

1. **整类移植**：类头标注 `@source` + `@changes`；
2. **方法级移植**：在原方法上保留来源注释，并在类头 `@changes` 汇总；
3. **仅参考设计/思路**：不标注 `@source`，但在分析笔记与 PR 描述中记录参考对象（避免"抄袭嫌疑"与"漏标"）；
4. **纯自研**：无需标注，但评审中确认未与 GPL 来源高度相似；
5. 判定模糊时按"宁多勿漏"处理（标注优于漏标）。

## 四、评审检查项（加入每个 T 的收口清单）

- [ ] 移植文件是否有 `@source`（模组名+原类名+版本）与 `@changes`（修改摘要）？
- [ ] MPL 文件是否保留 `SPDX-License-Identifier: MPL-2.0`，且未与 MIT 声明冲突？
- [ ] 是否出现 GPL 来源代码/近似实现？（一票否决）
- [ ] NOTICES 中的修改声明是否与标注集合一致？（可从标注汇总统计移植范围）
- [ ] 是否出现 intermediary 名（`class_XXXX`）直接写入业务代码？（一票否决）

## 五、与发布物的衔接

- 每个里程碑收口时，按 `@source` 汇总的实际移植范围更新 `licenses/THIRD-PARTY-NOTICES.md` 的"修改声明"；
- 发布前由 T7.4 复核：LICENSE + NOTICES + 协议原文齐备，MPL 文件头合规，GPL 零复制。

## 六、当前状态（T1.6 收口）

M1 业务代码全部自研（尚未复制任何参考模组代码）；本规范将首次实际应用于 M2 首个移植 PR，抽检要求：标注完整率 100%。
