# 线程边界规范（T1.3.4）

> 版本：v1.0（2026-10-31，M1/T1.3 实施）
> 依据：主说明红线 3（所有 OpenGL 操作仅在渲染主线程；资源随世界生命周期生命周期管理）、红线 4（唯一时间基准）。
> 适用范围：M2（视频）、M3（音频）、M4（网络输出）、M5（同步）及后续全部多线程代码；评审时逐表核对。
> 维护：实现与规范漂移时先改本文、再改代码并在任务验收记录注明；`verify-env.ps1`/代码评审为守护手段。

## 一、线程职责表

| 线程 | 创建方/命名 | 允许的操作 | 禁止的操作 | 备注 |
|---|---|---|---|---|
| **渲染主线程**（客户端主线程） | Minecraft 创建（`Render thread`） | 全部 GL 操作（FBO/PBO/纹理/GL 状态）、场景渲染、`RenderLevelStageEvent` 回调、状态保存/恢复、离屏渲染循环触发、`WorldResourceManager` 的 create/destroy | 阻塞等待网络/磁盘 IO；长时间 CPU 重活（JPEG 可选内联，但须控制在帧预算内） | 唯一 GL 线程；`GlThreadGuard.checkGlThread()` 强制 |
| **客户端主线程** | Minecraft 主线程（1.20.1 中与渲染线程为同一线程；必要时以 `Minecraft#execute` 投递） | 生命周期事件处理、配置加载、调度到渲染线程 | 直接执行 GL；跨线程共享可变状态 | 以 `RenderSystem.isOnRenderThread()` 判定为准 |
| **音频采集线程** | 本模组创建，命名 `captureapi-audio`（`CaptureConstants.THREAD_AUDIO`） | 从 OpenAL 环回缓冲读取 PCM、时间戳打标、写入环形缓冲、监听器同步的**调度**（GL/AL 操作投递渲染线程） | 任何 GL 调用；直接操作 OpenAL 设备上下文（除文档规定的采集读取外）；阻塞渲染线程 | M3 实现；线程优先级 MAX-1（附录 B `thread_priority`） |
| **网络 IO 线程** | 本模组/框架创建，命名 `captureapi-net`（`THREAD_NET`） | HTTP/WS 收发、帧/音频块广播、JSON 指令解析与校验、权限查询 | 任何 GL 调用；访问渲染线程持有的可变对象 | M4 实现；帧发布对象必须不可变 |
| **编码线程**（可选） | 本模组创建，命名 `captureapi-encoder`（`THREAD_ENCODER`） | JPEG 编码（`encode_async=true` 时）、有界队列消费 | 任何 GL 调用；访问 GL 对象 | M2 实现；有界队列满时丢旧并计数 |

> 说明：1.20.1 中客户端主线程即渲染线程（`RenderSystem.isOnRenderThread()` 为 true）；本表将"客户端主线程"与"渲染主线程"分列是为了明确职责语义，实现以守卫判定为准。

## 二、跨线程数据传递规则

1. **唯一合法穿越点**：跨线程数据只允许经通道传递——
   - 渲染线程 → 网络线程/其它消费端：`LatestValueChannel<T>`（仅保留最新，发布即不可变）；
   - 采集线程 → 消费线程（如音频环形缓冲）：`MpscRingBuffer<T>`（M3 实现，容量与丢帧策略由 M3 定义）。
2. **发布即不可变**：经通道的对象在发布后禁止修改；M2 帧对象须为防御性副本。
3. **禁止共享可变缓冲**：不得直接共享 `ByteBuffer`/`int[]` 等可变缓冲；确需共享时复制或改用不可变封装并在评审记录中说明。
4. **GL/AL 操作投递**：非渲染线程需要执行 GL 相关操作时，统一使用 `GlThreadGuard.runOnRenderThread(Runnable)`（内部 `RenderSystem.recordRenderCall`，1.20.1 已编译验证）；OpenAL 监听器改写同样在渲染线程执行（M3 的 `CameraSyncHook`）。
5. **生命周期事件**：世界进入/退出事件可能不在渲染线程触发；`WorldLifecycleHandler` 统一经渲染线程调度后再执行资源 create/destroy。

## 三、资源生命周期纪律（红线 3 配套）

- 世界级 GL 资源（FBO/PBO/纹理）经 `WorldResourceManager.registerWorldScoped()` 注册，随 `onWorldJoin()` 创建、`onWorldLeave()` 逆序销毁；禁止在渲染帧内每帧新建。
- 全局级资源（音频设备等）经 `registerGlobalScoped()` 注册，随客户端关闭（`shutdown()`）回收。
- 所有 GL 公开方法入口第一行调用 `GlThreadGuard.checkGlThread("<操作名>")`；M2/M3 评审项。
- 资源异常被管理器隔离并计数（`WorldResourceStats`），不阻断游戏主流程。

## 四、时间基准纪律（红线 4 配套，T1.4 接入后生效）

- 全模组唯一取时入口：`CaptureClock.nowNanos()`（T1.4 实现）；禁止 `System.currentTimeMillis()`/`Instant.now()` 参与帧/音频时间戳；`level.getGameTime()`/tick 计数不得作为音画时间源。
- `System.nanoTime()` 仅允许出现在 `CaptureClock` 内部（及明确的日志墙钟转换白名单 `LogTimeConverter`）。

## 五、评审检查清单（每个 T 收口时逐项）

- [ ] 新增 GL 代码是否全部在渲染线程、入口是否有守卫？
- [ ] 跨线程数据是否只经通道、对象是否不可变？
- [ ] 是否有每帧新建 GL 资源？（红线 3）
- [ ] 是否引入第二时间源？（红线 4）
- [ ] 线程命名是否符合本规范（`captureapi-*`）？
- [ ] 日志是否带 `[CaptureAPI]` 前缀且不含敏感信息？
