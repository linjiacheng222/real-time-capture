# 专用服部署指南（M9 服务端组件，v0.5.0）

## 一、组件与前置

| 项 | 要求 |
|---|---|
| Minecraft | 1.20.1 |
| Forge | 47.3.0+（推荐 47.4.28） |
| 客户端 | `captureapi-0.5.0.jar`（必须，含远程申请侧） |
| 服务端 | **`captureapi-0.5.0-server.jar`**（独立 jar，modid `captureapi_server`；**不要**把客户端 jar 放进 server mods） |
| Java | 17 |

产物位置：`build/libs/captureapi-0.5.0-server.jar`（build.ps1 产出，sha256 见安装脚本输出）。

## 二、安装

1. 关闭服务器；
2. 将 `captureapi-0.5.0-server.jar` 放入服务端 `mods/`；
3. 启动一次服务器，生成 `world/serverconfig/captureapi_server-server.toml`；
4. 按需修改（**必须无 BOM 保存**）：

```toml
[captureapi_server]
default_permission = true
permission_file = "config/captureapi/permissions.json"
max_chunks_per_player = 4096
max_chunks_global = 16384
max_requests_per_second = 20
```

5. 权限文件（相对服务端游戏目录，JSON，UUID→boolean；缺省取 `default_permission`；OP 恒允许）：

```json
{
  "380df991-f603-344c-a090-369bad2a924a": true,
  "另一个玩家UUID": false
}
```

6. 重启服务器使配置/权限生效。

> 也可用仓库脚本复制并校验 jar：
> ```powershell
> powershell -ExecutionPolicy Bypass -File scripts\install-server-component.ps1 -ServerModsDir "D:\server\mods"
> ```

## 三、客户端

- PCL 实例 mods 只放 `captureapi-0.5.0.jar`（不要放 server jar）；
- 加入服务器后，客户端日志期望：
  - `[REMOTE] 已发送 M9 握手（协议 v1）`
  - `[REMOTE] 握手响应：supported=true, serverProtocol=1, msg=OK`
- `/health` 期望：`remote_ready=true`，创建相机移动后 `remote_requests/remote_accepted` 增长。

## 四、验证（P1.3/P2.5）

1. 客户端进服，创建相机（`scripts\s1-capture-check.ps1` 或控制指令）；
2. 相机置于视距外（如 +250 格），等待区块加载；
3. 拉取 `/camera/0/frame` 确认远处地形出现；
4. 客户端断开，服务端日志应出现：
   `[TICKETS] releaseAll ... released=N total=0`；
5. 若把 `max_chunks_per_player` 调小（如 32），请求应返回 `E_PLAYER_LIMIT` 且 `accepted=0`；
6. 回传客户端/服务端日志与 `/health` 的 remote 字段。

## 五、故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 客户端无 `[REMOTE]` 日志 | 服务端未装 server jar / 通道版本不匹配 | 确认 server jar 在服务端 mods；客户端与 server jar 均 0.5.0 |
| 服务器启动报 `Invalid bare key`/`Failed loading config` | TOML 带 BOM 或手改格式错 | 用无 BOM UTF-8 重写/删除 `world/serverconfig/captureapi_server-server.toml` 让服务器重建 |
| `E_PLAYER_LIMIT` | 单玩家 ticket 上限 | 调整 `max_chunks_per_player` |
| `E_GLOBAL_LIMIT` | 全局限额 | 调整 `max_chunks_global` 或减少并发 |
| `E_RATE_LIMIT` | 申请频率超限 | 调整 `max_requests_per_second`；客户端 planner 默认 500ms 重算 |
| 客户端崩溃/找不到 TicketType | 把 **server jar** 误放客户端 | 客户端只放客户端 jar |
| 远处仍虚空 | 服务端未加载区块/权限拒绝 | 检查 `/health remote_last_code` 与服务端 `[TICKETS]` 日志 |
