## 2. 脚本清单与用法（`E:\捕获接口\scripts\`）

所有脚本：PowerShell 5.1/7 双兼容、UTF-8 BOM、`-ErrorAction Stop` 风格错误处理、路径由 `$PSScriptRoot` 自解析、
**脚本内自行设置 `JAVA_HOME`/`PATH`，不依赖调用者外部环境**；失败以非零退出码结束。
推荐在 PowerShell 中直接执行（本机 ExecutionPolicy CurrentUser=RemoteSigned，可直接运行）。

| 脚本 | 作用 | 常用参数 | 退出码 |
| --- | --- | --- | --- |
| `dev-env.ps1` | 定位/固定 JDK17，设置当前进程 `JAVA_HOME`/`PATH`；`-Persist` 写入用户级环境变量 | `-JdkHome` `-Persist` `-Quiet` | 0/异常 |
| `verify-env.ps1` | 全项环境自检，输出 PASS/FAIL 汇总表（35 项 + 5 条硬件 INFO） | `-SkipNetwork` `-SkipGradle` `-MarkdownOut <file>` | 0；有 FAIL=1 |
| `build.ps1` | `gradlew clean build`（`-SkipClean` 增量、`-Offline` 离线）+ 产物/mods.toml 元数据校验 | `-SkipClean` `-Offline` `-TimeoutSec` | 0/1 |
| `run-client.ps1` | 启动 dev 客户端，轮询 `latest.log`/`debug.log` 到主菜单，记录标记，结束 `taskkill /T` 清理并校验无残留 java | `-TimeoutMinutes`（默认 15）`-PollSeconds` `-GradleArgs` `-NoKill` | 0（到主菜单且无 crash/残留）/1 |
| `install-to-instance.ps1` | 把 `build\libs\captureapi-*.jar` 复制到 PCL 实例 mods，复制前后 SHA256 校验 | `-DryRun` `-Remove` `-JarPath` `-InstancePath` `-Force` | 0/1 |
| `prepare-dev-deps.ps1` | dev 依赖准备：用 ForgeGradle `fg.deobf` 把生产 jar 重映射为 named 变体放入 `run\mods\`；生产 jar 移至 `run\mods-original\` | `-Download` `-Offline` `-Force` `-TimeoutSec` | 0/1 |

常用命令：

```powershell

. .\scripts\dev-env.ps1
# 环境自检（建议每次重装/换机后执行）

# 构建（默认 clean build；离线验证用 -Offline）

# 启动 dev 客户端并自动清理（GUI 窗口出现属正常，不要点击）

# 升级 Embeddium/ModernFix 后重建 dev 依赖（首次需联网，之后可 -Offline）
```

> 提示：`. .\scripts\dev-env.ps1`（点源）才能在当前会话保留环境变量；直接 `.\scripts\dev-env.ps1`
> 只影响其子进程，但其余脚本均内置同等 JDK 解析逻辑，因此日常直接跑其余脚本即可。
> 用户级环境变量写入后，**新开终端**生效（极少数情况需重新登录或重启资源管理器）。

## 5. 故障排查（FAQ）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `java'/`javac` 找不到、`JAVA_HOME` 为空 | 新 shell 未加载用户变量 / 进程环境问题 | `. .\scripts\dev-env.ps1`；或直接运行其余脚本（内置解析） |
| 构建时依赖下载失败/超时 | 网络波动（GitHub 偶发连接重置） | `build.ps1 -Offline`；确认缓存完整（verify-env 检查） |

## 6. 已知问题与限制（重要）

1. **dev 环境不能直接加载生产（reobf/SRG）模组 jar（已解决，需用户知悉）**
   - 现象（2026-10-30 实测）：`run\mods` 直接放生产 `embeddium-0.3.31+mc1.20.1.jar` → `runClient` 在
     early display 阶段 FATAL：`InvalidMixinException: @Shadow method m_5601_ in embeddium... was not
     located in target class com.mojang.blaze3d.vertex.VertexConsumer` → `MixinApplyError` →
     `BUILD FAILED`。
   - 根因：dev 运行时是 Mojmap named 名字空间；生产 jar 被 reobf 成 SRG 硬名字。Mixin 的 `@Shadow`
     成员解析走 `MixinTargetContext.findRemappedMethod` → `environment.getRemappers()`（dev 下为空），
     **不经过 refmap**；仅在 `build.gradle` 加 `mixin.env.remapRefMap` 两个属性（只重映射 refmap 引用）
     无法修复（已实测：日志出现 `Remapping refMap ... using ...output.srg` 但仍在同一处崩溃）。
   - 解决：`scripts\prepare-dev-deps.ps1` 用 ForgeGradle `fg.deobf` 把生产 jar 重映射成 named 变体
     （`*_mapped_official_*_dev.jar`）放入 `run\mods\`，生产 jar 移入 `run\mods-original\`
     （Forge 只加载 `mods\` 顶层，不会加载该目录）。
   - 性质：这是 **dev 依赖的实现细节修正**，`run/mods 本地 jar` 机制（D-BUILD-1）不变；
     **需用户知悉/裁决**：是否长期维持该 dev 变体生成流程（或改用 `fg.deobf` maven 坐标依赖）。
   - 维护：升级 Embeddium/ModernFix 时，更新 `prepare-dev-deps.ps1` 顶部 `$Deps` 版本常量 → 重跑脚本。
2. **PowerShell 版本**：本机**没有 PowerShell 7**，实际为 Windows PowerShell 5.1.26100.9711。
   为「零手工可复现」，6 个脚本全部按 **PS 5.1 / PS 7 双兼容**编写（未使用 PS7-only 的 `-ie/-ine`、
   三元运算符、`??`、`utf8BOM` 参数等）。文档中的 `powershell`/`pwsh` 命令均可运行；若后续安装 PS7，
   脚本同样适用。
3. **首次运行需要联网**：`runClient` 首次会下载 Minecraft assets（本机已缓存 792.7 MB，
   `%USERPROFILE%\.gradle\caches\forge_gradle\assets`）；`prepare-dev-deps.ps1` 首次生成需要
   ForgeGradle/Forge 依赖（本机已缓存；离线可用 `-Offline` 验证通过）。重装环境后各需联网首跑一次。
4. **Oculus 未在 dev 加载**：按工程计划 P1 代码落地后再装；PCL 生产实例已有 `oculus-mc1.20.1-1.8.0.jar`，
   留给生产实例集成验收。
5. **「进入世界 / 游戏内行为」无法自动验收**：`run-client.ps1` 只验证到主菜单；进入世界、渲染/音频行为
   属人工验收项（GUI 窗口出现属正常，自动化不会操作游戏窗口）。
6. **GitHub 偶发连接重置**：`verify-env.ps1` 的 `git ls-remote origin` 已内置 3 次重试（首次实测曾偶发
   `Recv failure: Connection was reset`，重试即成功）。
7. **dev 变体是否会让 mods.toml 校验失败**：不会。变体保留原 `mods.toml`（modId/version 不变，如
   embeddium 0.3.31+mc1.20.1、modernfix 5.27.89+mc1.20.1），与 `gradle.properties` 的
   `embeddiumVersion/modernfixVersion` 及 `src/main/resources/META-INF/mods.toml` 的 mandatory 声明一致。
8. **构建产物未提交**：`build/`、`run/` 均在 `.gitignore` 中；证据文件位于工作区，不进入 git。
