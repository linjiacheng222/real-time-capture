# 多路视频流验收计划（用户操作版）

> 配套《多路视频流落地计划.md》。全部操作在游戏内完成——进一次世界，跟着做即可。共 6 个场景，约 15 分钟。
> 准备：启动 PCL 进入世界（任意存档）；另开一个 PowerShell 窗口。

---

## 场景 1：双相机各自出图（核心正确性）⏱ 约 3 分钟

**操作**：
1. 游戏内聊天框依次输入：
   ```
   /captureapi camera create pos:100,64,200
   /captureapi camera create pos:300,70,100 rot:180,0
   ```
   （此时相机 1 自动 active，相机 2 由时间片渲）
2. 等 5 秒，浏览器开两个标签页：
   - `http://127.0.0.1:25580/camera/1/frame`
   - `http://127.0.0.1:25580/camera/2/frame`
3. 各按 F5 刷新几次。

**通过标准**：
- [ ] 两个页面都显示**画面内容不同**的图（一个朝 200 方向、一个朝反方向）
- [ ] 响应头都有 `X-Frame-Timestamp`（且两个值不同）
- [ ] 无 502/无响应

**不通过现象速查**：页面 204→相机 2 没被渲（时间片没跑）；两图一样→帧存储串号。

---

## 场景 2：按相机异步截取（G3 核心）⏱ 约 2 分钟

**操作**：
1. 确保两台相机还在（`/captureapi camera list` 应显示 2 台）
2. 输入：
   ```
   /captureapi capture camera:2
   ```
3. 再输入：
   ```
   /captureapi capture camera:1
   ```

**通过标准**：
- [ ] 两条指令都返回"§a截取成功"带时间戳和字节数
- [ ] 两次截取成功消息中的帧来自**不同相机**（可通过紧接的 `/captureapi camera status` 对比，或加 `out:D:\cam1.jpg` / `out:D:\cam2.jpg` 打开图片对比视角）

**加强版**（可选）：
```
/captureapi capture camera:2 filter:grayscale quality:95 out:D:\cam2_gray.jpg
```
- [ ] 输出的 jpg 是灰度的

## 场景 3：WS 同时订阅多路（G2/G8）⏱ 约 3 分钟

**操作**：PowerShell 中运行：
```powershell
python -c "
import websocket, json, struct, time
ws = websocket.create_connection('ws://127.0.0.1:25581/', timeout=10)
ws.send(json.dumps({'id':'s1','action':'video.subscribe','params':{'cameras':[1,2]}}))
print('订阅响应:', ws.recv())
cam1 = cam2 = other = 0
start = time.time()
try:
    while time.time() - start < 8:
        d = ws.recv()
        if isinstance(d, bytes) and len(d) > 4 and d[0] == 0x04:
            cid = struct.unpack('<i', d[4:8])[0]
            if cid == 1: cam1 += 1
            elif cid == 2: cam2 += 1
        elif isinstance(d, bytes) and len(d) > 0 and d[0] in (1, 2):
            other += 1
except Exception as e:
    print('收流结束:', e)
print(f'8秒内: camera1帧={cam1}, camera2帧={cam2}, 旧格式帧={other}')
ws.close()
"
```
（无 python 环境则跳过本场景，标注"未验"）

**通过标准**：
- [ ] `camera1帧 > 0` **且** `camera2帧 > 0`（两路都有推送）
- [ ] 订阅响应 `"ok":true`

## 场景 4：懒渲染零开销（G4 性能）⏱ 约 2 分钟

**操作**：
1. 输入 `/captureapi info health`，记下 `视频渲染=` 的数字 A
2. **不打开任何相机 2 的页面/订阅**，等 30 秒
3. 再输入 `/captureapi info health`，记数字 B

**通过标准**：
- [ ] B − A ≈ active 路应有的帧数（30fps×30s≈900 左右），**没有**因相机 2 多出大量额外帧
- [ ] （若 `/health` 已含 `multi_rendered` 字段）`multi_rendered` 几乎不增长

**然后再**：浏览器打开 `/camera/2/stream` 看 10 秒，再查 health：
- [ ] `multi_rendered` 开始明显增长（有消费者才渲）

## 场景 5：按相机录像（V5）⏱ 约 3 分钟

**操作**：
1. ```
   /captureapi record start camera:2
   ```
2. 等 15 秒
3. ```
   /captureapi record stop
   ```
4. 打开输出路径的 mp4 文件（成功消息里有路径）

**通过标准**：
- [ ] 录像文件存在且 ≥ 15 秒内容
- [ ] 画面是**相机 2 视角**（与场景 1 中 camera/2 的图一致方向），不是 active 相机 1 的
- [ ] 帧数 > 30（约 15s×≥2fps）

---

## 场景 6：指令全参数组合（V6 收尾）⏱ 约 2 分钟

**操作**：
```
/captureapi capture camera:2 filter:grayscale overlay:水印@0.9,0.1,0.3,1,0,0.8 quality:90 audio:1 out:D:\final.jpg
```
（无叠加图时去掉 overlay 段）

**通过标准**：
- [ ] 一条指令同时生效：相机 2 视角＋灰度＋（若有）水印＋质量 90＋文件落盘
- [ ] 返回消息含 `→ D:\final.jpg`
- [ ] `D:\final.jpg` 打开是灰度、相机 2 视角

## 边界快速判据（给排障用）

| 现象 | 大概率原因 |
|---|---|
| camera/2/frame 一直 204 | 时间片没跑（multi_camera_fps=0？）或懒渲染没触发 |
| 两路画面相同 | CameraFrameStore 串号 / FrameRequest 未带 cameraId |
| WS 订阅后只收一种 camId | StreamPushService 判重逻辑漏另一路 |
| 多路开启后主画面明显掉帧 | 帧预算超限——调低 multi_camera_fps 或 budget_ms |
| capture camera:2 超时 | 等待者未被唤醒（V3 唤醒链路断） |
