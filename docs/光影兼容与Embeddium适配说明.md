# 光影兼容与 Embeddium 适配说明（T2.6 / T2.8）

> 状态：**代码骨架与验证方案已落位**（2026-10-31）。Oculus 离屏光影适配（I2.6.2）与四态矩阵实测（I2.8.3）归入后续《测试分计划》；按用户指示测试后置。
> 关联：T2.2.3 渲染管线、T2.3 主画面零扰动、I2.6.1~3、I2.8.1~3。

## 一、光影环境探测与 SPI（I2.6.1）

- 探测：`ModList.get().isLoaded("oculus")`、`isLoaded("embeddium")`，客户端 setup 日志打印；
- 挂点：`ShaderCompatHooks.detect()`；无光影时 `isActive()==false`，渲染管线**不调用** begin/end（无额外分支）；
- 有光影时管线在 FBO bind 后/解绑前调用 `beginOffscreenPass(pose)`/`endOffscreenPass()`；
- Oculus 内部 API 尚未查证（W-043），当前实现为**降级占位**：记录了入口但不改变离屏管线，光影开启时输出可能是无光影帧（待实装/上呈裁决 D-M2-2）。

## 二、Oculus 离屏 pass 适配（I2.6.2，待实装）

待办（按顺序）：
1. 查证 Oculus 1.20.1 对额外 FBO 的要求（shader 上下文/帧缓冲映射/后处理时机，W-043）；
2. 在 begin/end 钩子内实现绑定/恢复；
3. 光影开/关两态验收：开=离屏画面含光影且主画面无异常；关=与未启用捕获对照一致；
4. 若成本不可接受 → **上呈用户裁决**（D-M2-2），不自行决定降级语义。

## 三、无光影回归保障（I2.6.3）

- 两态（未装 Oculus / 已装但光影关闭）：T2.2~T2.5 全流程回归（限流、FBO 复用、回读、编码、主画面零扰动抽测）；
- SPI no-op 路径耗时与无 SPI 基线一致（微基准）；
- 纳入“每次光影/渲染相关改动”的固定检查单，M7 复用。
