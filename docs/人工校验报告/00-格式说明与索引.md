# 人工校验报告 · 格式说明与索引

> 本目录收录「必须由人工在真实客户端中执行并签字确认」的校验报告。按 D-HUMAN-1，验收人为用户。
> 创建时：报告先写清**需要执行的操作**与**理想反馈（期望现象）**，人工反馈区留空；执行后填写反馈并给出结论。
> 失败处理：由执行端尝试修复后，**在本目录内追加**修复尝试记录（见 §追加规则），不覆盖原始记录。

## 一、统一报告格式（人工校验）

编号规则：`MVR-M1-xx`。所有报告使用同一骨架：

1. 头部元信息：编号 / 类型 / 关联任务 / 创建日期 / 预期执行人 / 状态（初始「待人工填写」）/ 关联自动报告 / 证据提交位置；
2. `## 1. 目的与范围`
3. `## 2. 前置条件（环境、配置、世界/界面）`
4. `## 3. 操作步骤`（逐步、可照做，含日志/截图采集方式）
5. `## 4. 结果记录`（空表：检查项 / 期望 / 实际 / 证据 / 备注；**由人工填写**）
6. `## 5. 理想反馈与判定标准`（期望日志行、计数、现象、通过条件）
7. `## 6. 人工反馈区`（留空；填写执行人、日期、总体结论、异常描述、附件清单）
8. `## 7. 修复尝试记录（追加区）`（仅失败/异常时追加，按时间顺序，不覆盖历史）
9. `## 8. 附件与索引`（日志路径、截图命名、关联自动报告与验收记录）

## 三、追加规则（修复尝试）

1. 失败/异常由执行端尝试定位与修复；
2. 修复尝试记录**追加到对应 MVR 报告 §7**（新增「尝试 N（日期）」小节：现象 / 假设 / 修复动作 / 复验结果 / 结论）；
3. 如一次修复需要独立长日志，可在本目录新增 `MVR-M1-xx-追加-YYYYMMDD.md`，并在其头部引用原编号与失败现象；
4. 不覆盖、不改写已填写的人工反馈；原结论为「失败」的，修复复验后由执行端在 §7 追加「复验通过，建议重新执行步骤 X」并更新索引状态（改为「待复验」）。

## 四、人工反馈填写说明

- 「实际」列填：通过/失败/部分通过，附具体现象；
- 「证据」列填：日志片段路径（`run/logs/latest.log` 行号或副本）、截图文件名（建议 `docs/evidence/人工/MVR-M1-01-<序号>-<内容>.png`）；
- 「备注」列填：环境差异、操作偏差、疑问；
- §6 需填写执行人、日期、总体结论（通过/失败/部分通过）；
- 证据文件建议存放在 `docs/evidence/人工校验/`（可新建），并在 §8 列出清单。

## 五、与自动报告的关系

自动报告负责可机械化判定项；本目录负责真实客户端交互项。两侧通过编号互引；同一检查项只在对应一侧判定一次，避免重复结论。
