# 反编译分析工作流（I1.6.2）

> 状态：T1.6 实施（2026-10-31）。适用范围：M2/M3/M4 移植前的参考模组分析。
> 纪律：**只分析、不混入源码树**；所有分析笔记存放于工程外 `实时捕获/分析笔记/`（不进 `E:\捕获接口\src`）。

## 一、工具

- **首选**：IntelliJ IDEA 内置 FernFlower/Vineflower 反编译器（打开 jar → 反编译到内存视图）；
- **备选**：独立 CFR（`java -jar cfr.jar <jar> --outputdir <dir>`）或 `javap -p -c`（方法/签名/常量池级查询，本工程已用于 Forge API 核验）；
- 工具版本与运行记录写入对应分析笔记头部（工具名+版本+命令）。

## 三、笔记规范

1. 目录：工程外 `E:\PCL\.minecraft\versions\1.20.1-Forge_Get_Test\实时捕获\分析笔记\`；
2. 文件名：`<模组>-分析.md`（如 `Pixelshot-分析.md`）；
3. 每份笔记必须含：
   - 头部：对象版本 / 来源路径 / 工具与方法 / 分析日期；
   - 关键类清单：`原类名（Yarn/中间名）→ 拟落包名（本项目）→ 处理方式（移植/参考/不复用）`；
   - 关键方法/注入点：方法签名、注入点（HEAD/TAIL/INVOKE/Redirect）、线程与 GL 上下文；
   - 与 `W-xxx` 待验证项的逐项回填结果（W-003/004/005/006/008/009/011/014/015/023/024/025 等）；
   - 结论：对 M2/M3/M4 的可复用面与不可复用面、许可与标注要求。
4. **命名规则**：Fabric 产物中的 MC 类引用为 intermediary 名（如 `class_4225`）。笔记中只记录「intermediary/原方法名 → 经 T1.7 对照表换算后的 Mojmap 名」，**禁止把 intermediary 名直接写入业务代码**；模组自有类保留原 Yarn 类名。
5. 分析产出回填 `docs/附录A-映射对照表.md`（仅"已确认"条目可被代码引用）。

## 四、执行步骤

1. 解包/反编译 → 2. 类清单与关键调用链 → 3. 提取注入点与线程语义 → 4. W 项回填 → 5. 更新分析笔记与 T1.7 对照表 → 6. 迁移前评审（许可、线程、GL 边界）→ 7. 移植代码按《移植代码来源标注规范》标注。

## 五、与 T1.7 的关系

分析笔记只提供「事实与类名」；Yarn/intermediary→Mojmap 的映射**必须**经 `scripts/verify-mappings.py` 全链校验（Yarn→intermediary→official→Mojmap）后才能进入对照表"已确认"状态。未确认映射不得被业务代码引用。
